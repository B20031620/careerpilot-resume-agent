# 功能测试与产品化缺口审计

测试日期：2026-05-06

## 测试范围

本轮按真实用户路径测试，而不是只验证接口是否存在。

使用的真实文件：

- 本地桌面上的真实 DOCX 简历文件。为避免把个人信息写入仓库，本文档不记录具体文件名和正文。

测试链路：

1. 上传真实 DOCX 简历
2. 创建目标岗位 JD
3. 运行真实 DeepSeek 匹配分析
4. 创建真实模拟面试会话
5. 提交一轮面试回答并查看追问
6. 检查历史记录、用户隔离、润色、项目包装、职场沟通等页面是否具备真实功能

本报告不记录真实简历正文。

## 总体结论

当前项目具备基础工程骨架、部分 CRUD、文件上传、模拟面试和匹配分析入口，但距离“真实可用的求职助手产品”还有明显差距。

核心问题不是样式，而是产品闭环不完整：

- 没有用户系统，不同用户的数据无法隔离。
- 没有完整历史资产管理，用户很难找回简历、JD、面试记录和润色版本。
- 简历上传后只是提取文本，没有真正完成结构化解析。
- JD 创建后只是存原文，没有真正完成岗位画像分析。
- 真实 DeepSeek 匹配在本轮真实简历测试中超时失败。
- 简历润色不是编辑器，只是展示匹配建议，无法采纳、拒绝、改写、保存版本或导出。
- 项目包装、职场沟通页面仍是静态设计稿，没有接入后端和大模型。
- 长耗时 Agent 任务没有进度、任务状态、重试、取消、历史运行日志。

## 真实流程测试记录

### 1. 真实 DOCX 简历上传

结果：通过，但功能不完整。

后端可以读取真实 DOCX，并创建简历记录：

- source_type: `docx`
- raw_text_length: 1610
- parse_status: `pending`

问题：

- 上传成功后仍是 `parse_status=pending`，说明没有真正执行 AI 简历解析。
- 前端“简历分析”文案写的是“AI 深度结构化解析”，但实际只是提取文本并入库。
- 上传后没有预览确认步骤，选择文件后会直接创建简历记录，容易误操作和重复创建。
- 重复上传同一份文件会出现多条同名简历，没有去重、覆盖、版本管理。
- 不支持 PDF。

### 2. JD 创建

结果：通过，但功能不完整。

使用 `sample_data/jd_ai_agent_engineer.md` 创建 JD 成功。

问题：

- `analysis_status` 仍为 `pending`。
- 没有 JD 结构化画像，例如技能、经验、项目、关键词、优先级。
- 没有 JD 历史管理页面，用户只能在下拉框里看到标题。
- 岗位匹配页每次粘贴 JD 都会新建一条 JD，容易制造重复数据。

### 3. 真实 DeepSeek 匹配分析

结果：失败。

使用真实简历和真实 JD 调用 `/api/matches`，最终返回：

```json
{
  "error": "简历解析失败: Request timed out."
}
```

问题：

- 真实模型链路对长简历和长 JD 不稳定。
- 当前匹配流程是同步阻塞，用户只能看到“正在分析”，不知道卡在哪一步。
- 没有任务状态，例如 `queued/running/failed/succeeded`。
- 没有 AgentRun 可视化，也没有把失败原因保存成历史记录。
- 没有重试按钮、降级策略、分段解析、超时提示。
- 失败后不会生成任何可追踪记录，用户不知道刚刚发生了什么。

### 4. 真实模拟面试

结果：部分通过。

使用真实简历和真实 JD 创建模拟面试成功，DeepSeek 能生成贴合简历背景的问题。提交回答后也能生成评分和追问。

问题：

- 生成第一题耗时较长，页面缺少明确进度。
- 面试会话没有列表接口，`GET /api/interviews` 返回 Method Not Allowed。
- 刷新页面后，用户无法从页面找回正在进行或已完成的面试。
- 追问逻辑会保持相同 `turn_index`，前端进度容易显示为没有推进。
- 反馈字段太粗，只有 score、strengths、improvements、risks，缺少参考回答结构、扣分原因、改写建议。
- 最终报告没有稳定的历史入口。

### 5. 历史记录

结果：严重不足。

已有：

- `/api/reports` 可以列出匹配报告。
- 前端有“历史报告”页面。

缺失：

- 没有“我的简历”列表、详情、编辑、重新解析页面。
- 没有“我的 JD”列表、详情、编辑、重新分析页面。
- 没有“模拟面试历史”列表。
- 没有“润色版本历史”。
- 没有“Agent 运行历史”。
- 报告列表只显示“匹配分析”和分数，缺少简历标题、岗位标题、公司、失败状态、运行耗时。

### 6. 用户系统与数据隔离

结果：未实现。

文档 `docs/04_data_model.md` 设计了 users 和 user_id，但当前代码没有落地。

当前模型缺失：

- users 表
- auth/session/token
- resumes.user_id
- job_descriptions.user_id
- reports.user_id
- interview_sessions.user_id
- agent_runs.user_id

影响：

- 所有用户看到同一批简历、JD、报告和面试。
- 无法做“我的历史记录”。
- 无法支持多用户演示。
- 无法做个人 API Key、偏好设置和私有数据隔离。

### 7. 简历润色

结果：不是完整润色功能。

当前页面会再次调用匹配接口，然后展示 suggestions。

缺失：

- 没有真正的简历编辑器。
- 没有原文和改写后的 diff。
- 没有“采纳/拒绝/手动编辑/重新生成”。
- 没有生成新的简历版本。
- 没有导出 Markdown、TXT、DOCX、PDF。
- 没有按岗位生成定制化简历版本。

### 8. 项目包装与职场沟通

结果：静态页面。

缺失：

- 项目包装不能读取真实简历项目。
- 不能生成 STAR 故事。
- 不能保存项目故事版本。
- 职场沟通不能根据用户输入生成内容。
- 复制按钮没有实际复制逻辑。
- 场景和语气按钮只是视觉状态，不是真正可选参数。

## 优先级建议

### P0：先补真实产品闭环

1. 用户系统与数据隔离
2. 简历/JD/报告/面试历史资产管理
3. Agent 异步任务与运行状态
4. 简历解析和 JD 解析真正落库
5. 匹配分析超时与失败可恢复

### P1：补核心体验

1. 简历润色编辑器和版本管理
2. 面试历史、继续面试、报告复盘
3. 项目包装接入真实简历项目
4. 职场沟通接入 LLM
5. 上传预览、去重、重新解析

### P2：增强演示和维护

1. Demo 用户和样例数据
2. 端到端测试
3. AgentRun 调试面板
4. 导出 DOCX/PDF
5. 更完整的错误边界和空状态
