# 项目需求书

## 1. 项目名称

CareerPilot Resume Agent

中文名可使用：AI 简历润色与面试准备助手。

## 2. 项目背景

很多求职者在准备简历和面试时会遇到几个典型问题：

- 不知道简历和目标岗位 JD 是否匹配。
- 不知道项目经历应该如何表达，容易写成“流水账”。
- 不清楚面试官会围绕简历追问哪些问题。
- 缺少针对回答质量的反馈，只能自己反复猜测。
- 在职场沟通场景中，不知道如何组织措辞，例如催进度、谈薪、拒绝不合理安排、回复 HR。

普通大模型聊天可以解决一部分问题，但它通常缺少稳定流程、历史记录、结构化输出、可追踪执行过程和人审机制。这个项目的目标是用 LangGraph 将求职准备拆解为多个可维护的 Agent 工作流，让系统不仅能回答问题，还能按照明确步骤完成分析、评分、追问、反馈和报告生成。

## 3. 项目目标

### 3.1 产品目标

构建一个 Web 端 AI 求职准备系统，帮助用户完成从“简历诊断”到“岗位匹配”再到“模拟面试”的闭环。

系统需要支持：

- 上传或粘贴简历内容。
- 输入目标岗位 JD。
- 分析岗位能力要求。
- 分析简历与 JD 的匹配情况。
- 输出简历优化建议。
- 将项目经历包装成适合面试表达的版本。
- 根据 JD 和简历进行模拟面试。
- 对用户回答进行评分、追问和改写建议。
- 保存历史会话和报告，便于复盘。

### 3.2 技术目标

本项目不仅要能演示功能，还要体现 Agent 工程化能力：

- 使用 LangGraph 设计多节点、有状态、可恢复的 Agent 工作流。
- 使用 LangChain 集成 LLM、Prompt、工具调用、结构化输出。
- 使用 FastAPI 提供后端 API。
- 使用 React 或 Next.js 提供前端交互页面。
- 使用数据库保存用户、简历、JD、报告、会话等结构化数据。
- 使用向量库支持简历、JD、面试知识库检索。
- 使用 LangSmith 或日志系统追踪 Agent 执行过程。
- 预留模型切换、Prompt 版本管理、评测集和持续迭代能力。

## 4. 目标用户

### 4.1 主要用户

应届生、转行者、初中级开发者、准备跳槽的职场人。

### 4.2 次要用户

职业规划顾问、培训机构老师、技术面试辅导者、HR 初筛人员。

## 5. 核心问题

本项目优先解决以下问题：

1. 简历内容不够聚焦，无法突出和目标岗位相关的能力。
2. 用户不知道岗位 JD 背后真正需要哪些技能。
3. 用户不会把项目经历讲成“背景、任务、行动、结果”的面试表达。
4. 用户缺少真实面试追问训练。
5. 用户不知道自己的回答是否有逻辑漏洞或技术深度不足。

## 6. 功能范围

### 6.1 MVP 必做功能

#### 6.1.1 简历管理

用户可以上传或粘贴简历文本。

支持格式：

- MVP：纯文本、Markdown。
- 第二阶段：PDF、DOCX。

系统需要提取：

- 基本信息。
- 教育经历。
- 工作经历。
- 项目经历。
- 技能栈。
- 获奖、证书、开源经历。
- 自我评价。

#### 6.1.2 JD 管理

用户可以粘贴目标岗位 JD。

系统需要识别：

- 岗位名称。
- 公司或行业信息。
- 必备技能。
- 加分技能。
- 工作职责。
- 经验年限要求。
- 业务领域。
- 隐含能力要求，例如沟通能力、稳定性、工程化经验、数据分析能力。

#### 6.1.3 简历/JD 匹配分析

系统根据简历和 JD 输出：

- 总体匹配分。
- 技能匹配分。
- 项目匹配分。
- 经验匹配分。
- 表达质量分。
- 优势点。
- 短板点。
- 缺失关键词。
- 简历修改建议。
- 面试风险问题。

输出需要结构化，便于前端展示成卡片、雷达图、列表和报告。

#### 6.1.4 简历润色建议

系统不直接覆盖用户原简历，而是生成“建议修改版本”。

每条建议需要包含：

- 原始内容。
- 问题说明。
- 修改建议。
- 修改后版本。
- 修改原因。
- 风险提示，例如是否可能夸大事实。

用户可以接受、拒绝或继续调整。

#### 6.1.5 项目经历包装

用户可以选择某段项目经历，系统生成：

- 30 秒项目简介。
- 2 分钟项目讲解。
- STAR 结构版本。
- 技术亮点。
- 难点与解决方案。
- 可量化成果表达。
- 面试官可能追问。
- 建议补充的事实证据。

#### 6.1.6 模拟面试

系统基于简历和 JD 生成问题。

面试类型：

- HR 面。
- 技术一面。
- 技术二面。
- 项目深挖。
- 行为面试。

每轮流程：

1. Agent 生成问题。
2. 用户输入回答。
3. Agent 评价回答。
4. Agent 判断是否需要追问。
5. 进入下一题或生成阶段性报告。

评价维度：

- 是否正面回答问题。
- 逻辑结构。
- 技术深度。
- 真实性。
- 和 JD 的相关性。
- 表达清晰度。
- 风险点。

#### 6.1.7 职场沟通助手

支持用户输入职场沟通问题，例如：

- 如何回复 HR 邀约。
- 如何谈薪。
- 如何解释空窗期。
- 如何向领导说明延期。
- 如何拒绝不合理需求。
- 如何争取资源。

系统输出：

- 场景识别。
- 风险等级。
- 沟通策略。
- 推荐话术。
- 更强势版本。
- 更委婉版本。
- 不建议说的话。

#### 6.1.8 历史报告

系统保存：

- 每次简历分析报告。
- 每次 JD 匹配报告。
- 每次模拟面试记录。
- 每次职场沟通建议。

用户可以查看、删除、复制和重新生成。

### 6.2 第二阶段功能

- PDF/DOCX 简历解析。
- 简历版本对比。
- 一键生成目标岗位版简历。
- 面试语音输入。
- 面试回答录音转写。
- 多模型对比。
- 面试题库知识库。
- 岗位画像库。
- 个人成长计划。
- 邮件/日历提醒。

### 6.3 暂不做功能

MVP 阶段不做：

- 自动投递简历。
- 自动登录招聘网站。
- 自动伪造经历。
- 面向医疗、法律等高风险场景的职业建议。
- 复杂企业多租户权限系统。

## 7. 非功能需求

### 7.1 可用性

- 用户应能在 3 分钟内完成一次简历/JD 分析。
- 核心页面应清晰展示输入、分析中、结果、历史记录四类状态。
- Agent 执行中需要展示进度，例如“正在解析 JD”“正在分析项目匹配度”。

### 7.2 稳定性

- Agent 工作流失败时应保留已完成节点结果。
- 模型调用失败需要支持重试。
- 长流程应支持恢复，不应因为页面刷新丢失进度。

### 7.3 可解释性

- 每个匹配分数需要给出原因。
- 每条修改建议需要说明为什么改。
- 模拟面试评分不能只有分数，还需要指出证据。

### 7.4 隐私与安全

- 简历、JD、面试回答属于敏感数据。
- 日志中不应直接打印完整简历。
- API Key 不得提交到代码仓库。
- 用户可以删除自己的简历和报告。
- 对外部模型发送数据前，需要在隐私说明中告知用户。

### 7.5 可维护性

- Prompt 必须版本化。
- Agent Graph 必须按业务模块拆分。
- 输出必须尽量结构化。
- 数据库 schema 需要可迁移。
- 需要保留测试样例，方便迭代时做回归。

## 8. 验收标准

MVP 完成时，至少满足以下条件：

1. 用户可以创建一份简历记录。
2. 用户可以输入一个岗位 JD。
3. 系统可以生成结构化匹配分析报告。
4. 系统可以针对某段项目经历生成面试表达版本。
5. 系统可以完成至少 3 轮模拟面试问答。
6. 系统可以保存历史报告。
7. 后端有基本 API 文档。
8. 至少有 5 条样例测试数据。
9. README 能说明如何本地启动。
10. 面试展示时能在 5 到 8 分钟内完整演示一条主流程。

## 9. 面试展示重点

面试时不要只展示页面，要重点讲：

- 为什么这个场景需要 Agent，而不是简单聊天。
- 如何用 LangGraph 表达流程、分支、循环和人审。
- 如何把模型输出变成结构化数据。
- 如何保存 Agent 状态和执行记录。
- 如何避免 Prompt 越写越乱。
- 如何设计可持续维护的模块边界。
