# 用户场景文档

## 1. 用户画像

### 1.1 应届生用户

典型特征：

- 项目经历较少。
- 不知道如何表达课程项目、实习项目、竞赛项目。
- 容易堆技术名词，但缺少结果表达。
- 面试经验不足，不知道面试官会追问什么。

核心需求：

- 将普通项目经历包装成有逻辑的面试表达。
- 判断简历和岗位 JD 是否匹配。
- 提前准备常见追问。

### 1.2 转行用户

典型特征：

- 过往经历和目标岗位不完全一致。
- 简历中有大量非目标岗位经历。
- 不知道如何提炼可迁移能力。

核心需求：

- 从旧经历中提炼目标岗位相关能力。
- 降低“岗位不匹配”的风险。
- 准备转行动机和项目能力说明。

### 1.3 初中级开发者

典型特征：

- 有真实项目，但表达偏功能流水账。
- 技术深度表达不足。
- 对系统设计、性能优化、工程化实践总结不够。

核心需求：

- 优化项目描述。
- 深挖技术难点。
- 准备项目追问。
- 将工作内容转化为结果和影响。

### 1.4 准备跳槽的职场人

典型特征：

- 需要针对不同岗位定制简历。
- 需要准备谈薪、离职原因、职业规划等问题。
- 时间有限，希望快速获得高质量建议。

核心需求：

- 快速生成不同 JD 对应的简历建议。
- 准备 HR 面和行为面试回答。
- 获得职场沟通话术。

## 2. 主要用户旅程

### 2.1 简历/JD 匹配分析旅程

用户目标：判断自己的简历是否适合目标岗位，并获得修改建议。

流程：

1. 用户进入系统首页。
2. 用户上传或粘贴简历。
3. 用户粘贴目标岗位 JD。
4. 用户点击“开始分析”。
5. 系统展示 Agent 执行进度。
6. 系统输出匹配报告。
7. 用户查看优势、短板、关键词缺失。
8. 用户查看逐条简历修改建议。
9. 用户选择接受、忽略或重新生成建议。
10. 系统保存报告。

用户期望：

- 能看到明确分数。
- 能知道为什么扣分。
- 能看到可以直接改进的句子。
- 不希望系统虚构经历。

异常情况：

- 简历内容太短：系统提示用户补充项目经历。
- JD 内容太短：系统提示用户补充岗位职责和任职要求。
- 模型输出格式异常：系统重试或降级为普通文本报告。

### 2.2 项目经历包装旅程

用户目标：把一段项目经历改写成适合面试表达的版本。

流程：

1. 用户从简历中选择一个项目。
2. 系统展示项目原文。
3. 用户选择目标岗位方向，例如前端、后端、AI 工程、数据分析。
4. Agent 分析项目中的业务背景、技术栈、个人职责和结果。
5. Agent 提示缺失信息，例如“是否有性能指标”“是否有用户规模”“是否有难点”。
6. 用户补充信息。
7. Agent 生成 30 秒版本、2 分钟版本和 STAR 版本。
8. Agent 生成可能追问问题。
9. 用户保存项目讲解稿。

用户期望：

- 语言自然，不像模板。
- 能突出真实贡献。
- 能准备被追问的问题。

异常情况：

- 项目描述太空泛：Agent 先提问，而不是直接编造。
- 用户要求夸大经历：Agent 给出风险提示，并建议基于事实表达。

### 2.3 模拟面试旅程

用户目标：基于某个岗位进行面试训练。

流程：

1. 用户选择一份简历和一个目标 JD。
2. 用户选择面试类型，例如技术一面。
3. 系统生成面试计划。
4. Agent 提出第一道问题。
5. 用户输入回答。
6. Agent 评价回答，并判断是否追问。
7. 如果需要追问，Agent 继续提出追问。
8. 如果回答充分，Agent 进入下一题。
9. 完成指定题数后，Agent 生成面试报告。

报告内容：

- 总体评分。
- 强项。
- 主要问题。
- 高频风险点。
- 推荐补充知识点。
- 优化后的回答示例。

用户期望：

- 问题要贴合简历和 JD。
- 反馈要具体，不能只说“回答不错”。
- 追问要像真实面试官。

异常情况：

- 用户回答为空：系统提示重新回答。
- 用户回答偏离问题：Agent 先指出偏离，再给引导。
- 连续低分：Agent 降低问题难度或给提示。

### 2.4 职场沟通助手旅程

用户目标：获得适合场景的沟通策略和话术。

流程：

1. 用户输入问题，例如“我想和 HR 谈薪，怎么说”。
2. Agent 识别场景类型。
3. Agent 判断风险等级。
4. Agent 询问必要背景，例如薪资范围、当前 offer、目标薪资。
5. 用户补充信息。
6. Agent 输出沟通策略。
7. Agent 输出多种语气版本。
8. 用户选择保存或继续调整。

用户期望：

- 话术要自然。
- 不能太冒犯。
- 能说明为什么这么说。

异常情况：

- 涉及违法或不诚信行为：系统拒绝并给出合规建议。
- 信息不足：Agent 先追问关键背景。

## 3. 关键页面

### 3.1 简历工作区

展示：

- 当前正在处理的简历。
- 用户上传过的全部简历列表。
- 每份简历的解析状态、创建时间和操作入口。
- 将任意简历设为当前简历。
- 从当前简历直接进入岗位匹配、简历润色和模拟面试。
- 用户在其他业务页中途切换简历后，顶部当前简历和页面内选择项同步更新。

### 3.2 简历管理页

功能：

- 新建简历。
- 上传简历。
- 粘贴简历文本。
- 查看结构化解析结果。
- 删除简历。

### 3.3 JD 分析页

功能：

- 新建 JD。
- 粘贴岗位描述。
- 查看岗位能力画像。
- 保存常用岗位。

### 3.4 匹配分析页

功能：

- 选择简历。
- 选择 JD。
- 启动匹配分析。
- 查看分析进度。
- 查看报告。
- 接受或拒绝修改建议。

### 3.5 模拟面试页

功能：

- 选择面试类型。
- 查看问题。
- 输入回答。
- 查看反馈。
- 查看追问。
- 结束后生成报告。

### 3.6 职场沟通页

功能：

- 输入沟通问题。
- 选择语气风格。
- 查看策略和话术。
- 保存常用话术。

### 3.7 历史报告页

功能：

- 按类型筛选报告。
- 查看报告详情。
- 删除报告。
- 重新生成报告。

## 4. Demo 剧本

面试展示建议准备一条固定剧本：

1. 上传一份后端开发简历。
2. 粘贴一个 AI 应用开发岗位 JD。
3. 启动匹配分析。
4. 展示匹配分、短板、关键词缺失。
5. 选择一个项目经历，生成 2 分钟面试讲解稿。
6. 进入模拟面试，回答一题。
7. 展示 Agent 追问和评分。
8. 打开报告历史，展示保存结果。
9. 打开 LangSmith 或本地 trace，展示每个节点执行过程。

这个剧本可以在 5 到 8 分钟内完成，适合技术面试展示。
